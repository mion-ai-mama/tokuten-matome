## 1. プロジェクト概要

### 成果目標

Instagramで配布してきた全特典（GitHubページ / note記事 / プロンプト単体）を1枚の
ページに集約し、フォロワーがそこから全特典へ辿り着ける状態にする。今後新しい特典を
作った際は、一言伝えるだけで一覧に反映される運用を確立する。

### 背景・課題

特典が約30本に達し、置き場所が **GitHub Pages / note / DM内のプロンプト** の3種類に
分散している。過去の特典にフォロワーが辿り着けず、資産が埋もれている。
配布時も都度URLを探す手間が発生している。

### 成功指標

**定量**

| # | 指標 | 目標 |
|---|------|------|
| 1 | 掲載特典数 | 既存全件を掲載（掲載漏れゼロ） |
| 2 | 新特典の反映にかかるユーザー作業 | **0回**（「まとめに追加して」の一言のみ） |
| 3 | まとめページ→個別特典への遷移率 | 訪問者の50%以上が1枚以上カードをタップ |
| 4 | ページ表示速度 | スマホで3秒以内に表示完了 |
| 5 | リンク切れ | 常時0件 |

**定性**

- 迷わない: プロフィールのリンク1本で、過去特典が全部見つかる
- 選べる: カテゴリーと検索で、自分に必要なものをすぐ絞れる
- 増える前提で壊れない: 特典が50本になってもユーザーはコードを触らない
- 世界観が揃う: 既存特典ページと同じ大人ピンク×アイボリーで一貫している

## 2. システム全体像

### 機能一覧

| ID | 機能 | 概要 |
|----|------|------|
| F-01 | 特典カード一覧 | 全特典をカードグリッドで表示。件数を自動計算 |
| F-02 | カテゴリー絞り込み | 3カテゴリーのタブ切替。該当件数をリアルタイム表示 |
| F-03 | キーワード検索 | タイトル・説明・タグを対象にインクリメンタル検索 |
| F-04 | 種別バッジ | 特典ページ / note / プロンプト の3種を見分ける |
| F-05 | プロンプト表示・コピー | プロンプト単体特典をページ内で開き、ワンタップでコピー |
| F-06 | プロフィール表示 | 名乗り・Instagram導線 |
| F-07 | CTA | 『AIマネタイズの教科書』バナー（常時表示） |
| F-08 | 該当0件時の案内 | 条件に合う特典が無い場合のメッセージ表示 |

### ロール・認証要件

認証機能は**なし**。全コンテンツが一般公開。ログイン・会員管理・個人情報の取得は行わない。

### 特典の3種別

| 種別 | バッジ | 挙動 | 本数（初期） |
|------|--------|------|------|
| `page` | 🎁 特典ページ | 個別のGitHub Pagesへ遷移（別タブ） | 14 |
| `note` | 📝 note | note記事へ遷移（別タブ）＋**外部遷移の注釈を表示** | 11（`note.com/brisk_ibis4395`） |
| `prompt` | 📋 プロンプト | **ページ内**で本文を開き、コピーボタンで即コピー | 1 |

#### note型カードの注釈（確定）

`type: "note"` のカードには、タップ前に気づける位置（カード下部）へ必ず次の一文を出す。

> こちらの特典は外部サイト note に遷移します

意図せぬ離脱を防ぎ、「今どこへ行くのか」が分かる状態を保つため。
GitHubページ型・プロンプト型のカードには表示しない。

### カテゴリー定義（テーマ軸に統一）

「プロンプト集」等の*形式*はカテゴリーではなく**タグ**で表現する。
軸を混ぜると1件が複数カテゴリーに該当し、絞り込みが破綻するため。

| カテゴリー | 内容 |
|-----------|------|
| ChatGPT・AI活用 | AIそのものの使い方・対話・プロンプト技術 |
| 画像・動画づくり | 画像生成・イラスト・動画・スタンプ等の制作 |
| AIで副業・在宅ワーク | 収入につながる実践（販売・受注・執筆・制作案件） |

## 3. ページ詳細仕様

### P-001 特典まとめページ（`index.html`）

- **ページID**: P-001
- **ルート**: `/`（`https://mion-ai-mama.github.io/tokuten-matome/`）
- **目的**: 全特典への入口を1枚に集約する
- **権限**: 誰でも閲覧可

#### セクション構成

| # | セクション | 内容 | 対応機能 |
|---|-----------|------|---------|
| 1 | ヒーロー | キャッチコピー ／ 総件数を自動表示 ／ 一覧へのスクロール導線 | F-01 |
| 2 | プロフィール | みおん｜在宅ワークの3児ママ ／ `@mion.ai.mama` へのリンク | F-06 |
| 3 | 絞り込みバー | カテゴリータブ＋キーワード検索。該当件数を表示 | F-02, F-03 |
| 4 | 特典カード一覧 | サムネ・番号・カテゴリー・タイトル・説明・タグ・種別バッジ。並び順は下記 | F-01, F-04 |
| 5 | プロンプト表示 | `prompt` 種別のカードをタップで展開。コピーボタン付き | F-05 |
| 6 | CTA | 『AIマネタイズの教科書』バナー | F-07 |
| 7 | フッター | Instagram導線 ／ 著作権表示 | F-06 |

#### 並び順（確定）

**種別グループ順 → 各グループ内で新着順**の2段階で並べる。

```
① 🎁 特典ページ型（page）… 新着順      ← 一番上
② 📝 note型（note）      … 新着順
③ 📋 プロンプト型（prompt）             ← 一番下
```

自分のページへ来てほしいものを上に置き、外部サイトへ離脱するnoteを下げるため。

> ⚠️ **今後の追加で間違えやすい点**: 新しい特典は「配列の一番上」ではなく
> 「**その種別グループの一番上**」に入れる。たとえば新しいnote特典を追加しても、
> ページ全体の先頭ではなく note グループの先頭に入る。
>
> 初期26件は偶然、GitHubページ型（2026-07-30以降）がnote型（〜2026-07-24）より
> すべて新しいため、結果的に純粋な新着順と一致している。この一致に依存しないこと。

並べ替えのUIは持たない（ユーザーが並び順を変える機能は作らない）。

#### 処理フロー

```
ページ読込
  → presents.js の PRESENTS 配列を読む
  → 総件数・カテゴリー別件数を算出して表示
  → カードを描画（配列の順＝表示順。page群 → note群 → prompt群、各群は新着順）

カテゴリータブをタップ / 検索語を入力
  → 配列をフィルタして再描画（該当件数も更新）
  → 0件なら案内メッセージを表示（F-08）

カードをタップ
  ├ type: page  → 個別ページへ（別タブ）
  ├ type: note  → note記事へ（別タブ。カードに外部遷移の注釈を常時表示）
  └ type: prompt→ ページ内でプロンプト本文を展開（F-05）
                   → コピーボタンで clipboard へコピー、完了表示
```

## 4. データ設計概要

### 単一の真実の源

`js/presents.js` の `PRESENTS` 配列。**この配列に1件追記すれば、カード・カテゴリー
件数・総件数がすべて自動で更新される**（手作業でHTMLを触る箇所は存在しない）。

### エンティティ: Present（特典1件）

| フィールド | 型 | 必須 | 内容 |
|-----------|-----|------|------|
| `id` | string | ✅ | 一意の識別子（kebab-case。例: `chatgpt-10-codes`） |
| `number` | string | ✅ | 表示番号（`"01"` 形式・自動採番） |
| `type` | `"page"` \| `"note"` \| `"prompt"` | ✅ | 特典の種別 |
| `category` | string | ✅ | 3カテゴリーのいずれか |
| `title` | string | ✅ | カード見出し。**長い元題は短く言い換えてよい**（`<br>` 可） |
| `plainTitle` | string | ✅ | **元のタイトル全文**（検索対象。言い換えても検索性を落とさないため） |
| `description` | string | ✅ | 説明文（60〜90字目安） |
| `tags` | string[] | ✅ | タグ3つ程度 |
| `url` | string | △ | `page` / `note` のとき必須。`prompt` では未使用 |
| `prompt` | string | △ | `prompt` のとき必須。コピー対象の本文 |
| `image` | string | ✅ | サムネイル画像のパス |

### バリデーション（追記時に守る規約）

- `id` は全件で重複しないこと
- `type: "page"` / `"note"` は `url` 必須、`type: "prompt"` は `prompt` 必須
- `category` は定義済み3種以外を使わない（絞り込みから漏れるため）
- `image` は必ず存在するファイルを指すこと（壊れ画像を出さない）

### サムネイル生成方針（ハイブリッド・確定）

| 条件 | 方針 |
|------|------|
| 固有のヒーロー画像がある（既存8本） | その画像を `assets/thumbs/` に取り込んで使用 |
| 固有画像がない / OGPがCTAバナー共通（既存6本） | **タイトルからデザインを自動生成**（大人ピンク×アイボリー） |
| note特典・プロンプト特典 | 原則として自動生成 |

自動生成の仕様: 800×600px、アイボリー基調のグラデーション、左端にピンクのアクセント
ライン、番号・カテゴリーピル・タイトル（キーワードにピンクのマーカー）・説明文・
タグ・`@mion.ai.mama` を配置。ヘッドレスChromeでHTMLをレンダリングして書き出す
（外部サービス・API不要、コスト0円）。

## 5. セキュリティ要件

静的サイトのため攻撃面は極小。以下を満たす。

- **HTTPS強制**: GitHub Pagesの標準機能（Enforce HTTPS）を有効にする
- **入力値サニタイゼーション**: 検索ボックスの入力・`PRESENTS` の値をDOMへ挿入する際は
  必ずエスケープする（`innerHTML` への生値挿入を禁止。XSS対策）
- **外部リンク**: `target="_blank"` には `rel="noopener noreferrer"` を必ず付与
  （タブナビング対策）
- **個人情報**: 取得・保存しない。フォーム・Cookie・トラッキングを設置しない
- **秘密情報**: APIキー・認証情報を一切持たない。`.env` 系ファイルを作成しない

ヘルスチェックエンドポイント・グレースフルシャットダウンは、サーバープロセスが存在
しないため該当なし。

### CVSS 3.1 相当の評価

| 想定脅威 | 評価 | 対策 |
|---------|------|------|
| XSS（検索語・データ経由） | Medium | DOM挿入時のエスケープを徹底 |
| タブナビング | Low | `rel="noopener noreferrer"` |
| リンク先の乗っ取り・リンク切れ | Low | 掲載URLは追加時に到達確認する |
